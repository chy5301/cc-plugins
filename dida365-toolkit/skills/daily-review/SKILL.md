# 滴答清单每日回顾

查看今日待办、逾期任务和整体任务概览，帮助用户规划一天的工作。

通道选择、工具命名发现、能力发现协议、批量部分失败、安全边界与失败分类统一见 `${CLAUDE_PLUGIN_ROOT}/references/tool-conventions.md`；使用任何滴答清单能力之前先读该文件，本文只补充回顾流程与完整性说明。

## 只读边界

本 skill **只查询、只呈现，不修改任何数据**。回顾中看到任务该完成、该延期、该改优先级、该归类，都只是在报告里提示用户，由用户自己决定；**不要顺手完成、移动、删除任务，也不要改动清单**——那些是 task-complete、task-organize、project-management 的职责，未经用户明确要求就写数据违背"回顾"这个动作本身的预期。用户要求执行时，先明确他要做的操作，再转入对应 skill。

## 接入前提

- **默认 Bearer 接入**：仅插件 `headersHelper` 模式要求默认凭据文件 `~/.dida365/token`；环境变量 `DIDA365_API_TOKEN` 是**可选且优先**的本地/API 来源，不能替代该模式的默认凭据文件（见 `tool-conventions.md` 第 8 节与 setup-guide）。
- **已有 OAuth MCP 接入**：已认证且可用的手动 OAuth MCP 不需要个人 Token 或默认凭据文件，直接使用当前连接的工具；不因文件缺失转入 setup-guide，也不要求运行 Token helper 自检。
- **API 补缺**：只有确认 MCP 缺口、需要正式调用 API 时才要求个人 Token；缺少时说明限制，由用户选择补配或在滴答应用中完成，不读取 OAuth 缓存，不改动现有 OAuth MCP。
- 没有可用 MCP 接入或调用返回 401 时，说明原因并按当前认证方式转入 setup-guide；403 按权限问题处理。不自动切换通道或认证方式，也不在本 skill 里改配置。
- 失败按 `tool-conventions.md` 第 9 节分类处置；超时或结果不确定时先只读核验现状，不重试、不换通道重做。

## 执行流程

### Step 1: 发现工具并获取清单列表

先查看当前连接实际暴露的工具与 schema，按语义选择（清单列表、清单详情、条件筛选、已完成查询、单任务读取等）。工具名与参数以发现结果为准——插件模式下形如 `mcp__plugin_dida365-toolkit_dida365__<tool>`，OAuth 手动配置模式下命名空间可能不同；**不得凭记忆拼工具名，也不得写死唯一前缀**。

然后取清单列表，记录清单 ID 与名称：

> **清单列表是分页的，且不包含虚拟 inbox**。按分页继续跟页，不要在第一次返回后停下；也不要因为清单列表为空就判断账号没有任务——空列表只说明这一页没有清单。

### Step 2: 读取 inbox

单独读取虚拟 inbox（收集箱）的任务：分页清单列表不含 inbox，只依赖 Step 1 的清单枚举会把 inbox 里的快速记录任务整块漏掉。inbox 中通常包含未分类的快速记录任务，需要单独成组展示。

### Step 3: 筛选今日任务

按当天日期范围筛选未完成任务，日期写完整 ISO 8601 并带明确时区，结合当前日期自行解析（如 `2026-04-04T00:00:00+0800` 至 `2026-04-04T23:59:59+0800`）：

- 本次迁移不再承诺短日期会被转换，不要传 `2026-04-04` 这样的短日期。
- **先确认筛选工具支持的日期字段是开始日还是截止日**：不支持按截止日筛选时，开始日筛出的结果不是"今天到期"；此时逐清单读取今日范围的任务，在结果中按 `dueDate` 分档，并说明覆盖了哪些清单。

### Step 4: 查找逾期任务

逾期指**截止日已过**且仍未完成的任务。分两种情况处理，**不得只按开始时间粗筛就宣称逾期清单完整**：

1. **筛选工具支持按截止日筛选**：按截止日早于今天 + 未完成筛选，直接得到候选集。
2. **筛选工具只支持开始日**：开始日已过只是粗筛（任务可能还没到截止日，也可能没有截止日），**不代表逾期**。此时枚举所需清单（含 inbox），逐个读取任务，再在结果中筛 `dueDate` 早于今天且 `status` 为 `0` 的任务。用粗筛缩小范围时，必须在报告里说明这是粗筛结果、不是完整逾期清单。

无论哪种情况，都按 `tool-conventions.md` 的部分失败规则说明**失败、截断与未覆盖范围**：哪些清单读取失败或结果未知、分页是否跟完、有哪些清单没有检查。没有逐个检查截止时间时，不要用"逾期任务已全部列出"这类表述。

不要用 `completedTime` 判断是否完成：实测放弃也会写入该时间，恢复为未完成时不保证清除（见 `tool-conventions.md` 第 7 节）；以 `status` 为准。

### Step 5: 筛选高优先级任务

筛选未完成 + 优先级 `3`（中）或 `5`（高）的任务，作为"值得今天关注"的一档展示。

### Step 6: 汇总展示

将以上信息整理为结构化的回顾报告，沿用固定骨架：

```
## 📋 今日任务回顾

### 🔴 逾期任务（X 项）
| 任务 | 清单 | 截止日 | 优先级 |
|------|------|--------|--------|
| ...  | ...  | ...    | ...    |

### 📌 今日待办（X 项）
| 任务 | 清单 | 优先级 |
|------|------|--------|
| ...  | ...  | ...    |

### ⭐ 高优先级（未安排日期）（X 项）
| 任务 | 清单 | 优先级 |
|------|------|--------|
| ...  | ...  | ...    |

### 📥 收集箱（inbox）（X 项）
- 任务1
- 任务2

### 覆盖范围
- 已检查的清单：...
- 未覆盖/失败/截断：...
```

### Step 7: 提供建议

根据任务情况向用户提供建议（只建议，不代为修改）：

- 如果有逾期任务，建议优先处理或调整截止日期；
- 如果今日任务较多，建议关注高优先级项；
- 如果收集箱有未分类任务，建议归类到对应清单（可由用户确认后使用 task-organize skill）；
- 如果用户需要更灵活的条件筛选或统计，引导使用 task-query skill。

## 完整性说明

回顾的结论必须交代覆盖范围，避免把不完整的数据说成全部：

- **覆盖**：查过哪些清单、是否包含 inbox、用的是哪个日期字段、日期范围是什么。
- **截断**：清单列表分页未跟完、或某次查询命中上限时，明确说明"结果可能不完整"。
- **失败**：某清单读取失败、超时或结果未知时，逐项说明，不把部分结果写成完整回顾（见 `tool-conventions.md` 第 6、9 节）。
