# 滴答清单官方 API 与 MCP 参考

本文件不复制官方端点表，只保留可信来源、服务范围、MCP 缺口发现流程与已验证的限制。字段、参数与返回结构以官方文档和运行时发现到的实际 schema 为准。

## 可信来源

- 官方 API 文档（Markdown）：<https://developer.dida365.com/docs/openapi.md>
- 官方 MCP 帮助页：<https://help.dida365.com/articles/7438132116019216384>
- 官方 MCP 服务地址：`https://mcp.dida365.com`
- 通道选择、发现协议、安全边界与失败分类见同目录 `tool-conventions.md`

## 服务范围

**本版本仅支持国内**滴答服务：

- API 出口固定 `https://api.dida365.com`，MCP 出口固定 `https://mcp.dida365.com`。
- 国际 TickTick（`api.ticktick.com` 等）本次不再支持；可识别的国际/其他域名配置会在发送任何凭据之前失败，不做静默降级。
- 不能从未知 Token 字符串识别地区；本文档也不承诺国际服务的任何行为。

## MCP 优先，API 只做补缺

任务、清单、状态、移动、批量创建与批量更新等常用能力已由官方 MCP 覆盖（工具清单为调研快照，运行时重新发现）。默认全部走 MCP；只有 MCP 明确缺少工具或必需参数（例如删除单个清单）时，才调用通用 API 执行器的补缺路径。MCP 调用失败（401/403/429/超时/参数错误）是运行失败，不是能力缺口，不构成切换通道的理由。

## 补缺发现流程

1. 在官方文档确认存在该能力，记录方法、路径、参数与限制。
2. 按操作语义判断是否只读（官方存在 POST 查询接口，不能只看 HTTP 动词）。
3. 文档不能明确支持时停止，不猜内部接口、不试探未证实的参数。
4. 用 `uv run ${CLAUDE_PLUGIN_ROOT}/scripts/dida365_api.py` 构造请求，写操作先加 `--dry-run` 展示方法与路径。已知案例：删除清单为 `DELETE /open/v1/project/{projectId}`（先确认清单身份与连带删除影响）。
5. 执行后读回核验；结果不确定时先只读查询现状，不盲目重试。
6. 新发现的接口不自动成为长期支持能力；确需长期支持时另行审核并写入 Skill 或参考文档。

## 已验证限制（截至 2026-10-08）

- **status 取值**：任务 `-1`=已放弃、`0`=未完成、`2`=已完成；checklist item 完成值为 `1`。实测放弃会写入 `completedTime`，恢复为未完成时不保证清除该时间——不要用 `completedTime` 判断状态。schema 可传值不等于业务效果已被验证，放弃/恢复/已完成恢复行为见下方实测记录。
- **无官方 OpenAPI JSON 规范**：官方只提供 Markdown 文档，未确认存在可下载的 OpenAPI JSON/YAML 规范；本插件不依赖、也不自行生成完整规范。
- **分页清单列表不含 inbox**：MCP 的分页清单列表不包含虚拟"收集箱"，清单列表为空不代表账号没有任务；需要时单独读取 inbox，不要因为分页漏掉它。
- **`--fields` 不减少网络下载量**：字段投影只在输出侧裁剪顶层字段，响应仍会完整下载，也不支持嵌套裁剪。
- **移动语义**：使用官方移动能力（MCP 的移动工具），不用"复制 + 删除"模拟。
- **日期语义**：开始日、截止日、完成日是三种不同语义，需分别对应到工具的筛选字段；日期必须带明确时区与当前日期。本次迁移不再承诺短日期会被转换，请传完整 ISO 8601（如 `2026-04-05T14:30:00+0800`）。
- **批量操作无原子性保证**：不能沿用其他工具的批次数值，也不宣称批次原子性；逐项结果按 `tool-conventions.md` 的部分失败规则处理。
- **文档声明 ≠ 实测结论**：写能力的声明不得写成实测成功结论；只有实际验证过的限制才写入本文件。

### 写入验收实测记录（2026-10-08）

以下为临时清单/临时任务的真实账号实测（对象事后已删除），只记录行为事实：

- 已完成任务可经 `status=0` 恢复；`completedTime` 在恢复后残留、不清除（展示状态只信 `status`）。
- 放弃（`status=-1`）同样会写入 `completedTime`。
- `batch_update_tasks` 混入不存在的 id 时：整调用返回错误（`unknown_exception`，无逐项明细），但**有效项已生效**——即“部分生效 + 整调用报错”。据此按部分失败规则处理：先只读核验实际结果，不整批重放。
- 删除清单（`DELETE /open/v1/project/{projectId}`）成功，并**级联删除该清单内的任务**；执行后已读回确认。
