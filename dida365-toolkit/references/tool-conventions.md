# dida365-toolkit 工具通道约定

本文档是七个 Skill 统一引用的通道约定：默认走官方 MCP，仅在确认缺口后按能力发现协议调用通用 API 执行器。使用任何滴答清单能力之前先读本文件；各 Skill 只补充自己的工作流细节，不重复这里的规则。官方端点来源与已验证限制见 `references/api-reference.md`。

---

## 1. 通道选择

- **默认使用官方 MCP**：任务、清单、状态、查询与移动等操作优先用 `.mcp.json` 注册的 `dida365` 服务完成。
- **仅在确认缺口时补缺**：只有 MCP 明确缺少所需工具或必需参数时，才进入第 2 节的 API 补缺路径。
- **禁止把运行失败当作切换理由**：MCP 调用返回 401/403/429、超时或参数错误时，按第 9 节分类处置；不得因此改用 API 重发同一操作，也不得因此更换认证方式。
- 认证方式（默认个人 API Token，OAuth 为用户明确选择的备选）由用户决定，任何失败不得自动切换。

## 2. 能力发现协议

MCP 缺口路径固定七步：

1. **查官方文档**：先确认是"缺少工具或必需参数"，而不只是遭遇调用错误；在 `references/api-reference.md` 可信来源处核对方法与路径。
2. **记录请求要素**：记下 HTTP 方法、路径、参数、返回结构与已知限制，注明依据来源。
3. **按语义判断只读**：不能只看 HTTP 动词。官方存在 **POST 查询接口**（如查询已完成任务、条件筛选），按操作语义判断是否只读，而不是按 GET/POST。
4. **文档不支持即停止**：官方文档不能明确支持的接口，说明限制并停止；不猜内部接口、不试探未证实的参数。
5. **先 `--dry-run` 展示**：写操作先用 `--dry-run` 展示方法、路径与请求体（不含凭据），确认无误后再正式执行。预演是本地构造，不等于服务端验证。
6. **在用户授权范围内执行**：按用户已给出的授权执行；探索性写操作、删除清单等影响不明确的操作，先明确确认范围再动。
7. **读回核验**：执行后读回核验。结果不确定时先只读查询现状，不盲目重试。

新发现的接口不会因为一次调用就自动扩大长期支持范围；确需长期支持时另行审核并写入 Skill 或参考文档。

## 3. 工具命名发现

- 插件模式下，当前 MCP 工具名形如 `mcp__plugin_dida365-toolkit_dida365__<tool>`。
- OAuth 手动配置模式下命名空间可能不同：必须查看当前实际连接的服务与工具 schema 后再调用，**不得写死唯一前缀**，也不得凭记忆拼工具名。
- 工具名、参数与输出以当前发现到的 schema 为准；文档中的清单只是调研快照，运行时重新发现。

## 4. 平台消歧

与 mstodo 等其他待办工具并存、用户未指明平台、且上下文无法确定时，先向用户澄清平台再执行。不要仅凭 Skill 描述或用户口头用词猜测平台；本轮上下文已明确在操作滴答清单时可直接执行。

## 5. API 执行器用法

API 补缺统一走通用执行器 `scripts/dida365_api.py`：PEP 723、`uv run` 执行、单次请求、固定出口、不重试。

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/dida365_api.py --method <METHOD> --path <PATH> [--query '<JSON>'] [--body '<JSON>'] [--fields a,b] [--dry-run]
```

- `--method`：GET / POST / PUT / PATCH / DELETE。
- `--path`：必须以 `/open/v1/` 开头的相对路径，不接受绝对 URL、查询串或路径穿越。
- `--query`：查询参数 JSON 对象；`--body`：请求体 JSON 对象或数组。
- `--fields`：输出 data 的顶层字段投影（逗号分隔），列表则逐项裁剪；**不减少网络下载量**，也不支持嵌套裁剪。
- `--dry-run`：输出请求概要，不发请求、不需要 Token，退出码 `10`；预演不是服务端验证。

可直接复制使用的示例：

```bash
# 预演：确认方法、路径与请求体（不发请求、不需要 Token）
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/dida365_api.py --method POST --path /open/v1/task --body '{"title":"示例"}' --dry-run

# 只读查询：列出清单并裁剪顶层字段
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/dida365_api.py --method GET --path /open/v1/project --fields id,name

# 删除清单补缺：先用 --dry-run 展示目标与连带影响，确认后再去掉 --dry-run 正式执行
uv run ${CLAUDE_PLUGIN_ROOT}/scripts/dida365_api.py --method DELETE --path /open/v1/project/<id> --dry-run
```

Token 不出现在命令行参数、请求体或任何输出中；凭据由共享认证模块在发送前注入。

## 6. 批量结果与部分失败

批量操作（批量创建、批量更新、批量完成、移动）按下述规则处理：

1. **逐项区分**：执行前保留每项的目标标识或可核验的关联信息；执行后依据实际逐项结果，分别报告**成功、失败、结果未知、尚未提交**，不把部分成功写成整批成功。
2. **不推断**：返回缺少逐项结果、部分响应或中途超时、且无法确认整体效果时，相关项归入结果未知；不能仅凭 HTTP 成功或工具未抛错就推断每项都成功。
3. **未知项先只读核验**：通过只读查询确认现状；没有可靠关联信息时说明无法确认，不凭相似标题猜测创建结果。
4. **不自动重放**：不自动重放整批，也不重放已确认成功的项。确需继续时，按原授权范围或重新确认后的范围，只处理已确认未生效且用户允许的项。
5. **不引入机制**：不新增事务、恢复状态库或重试引擎；上述规则属于 Skill 编排与反馈契约。

## 7. 状态语义

| 对象 | 取值 | 含义 |
|---|---|---|
| 任务 `status` | `-1` | 已放弃 |
| 任务 `status` | `0` | 未完成 |
| 任务 `status` | `2` | 已完成 |
| checklist item `status` | `1` | 已完成（子任务完成值，与任务的 `-1/0/2` 不同） |

- 以当前 schema 与实际验证结果为准；`status` 字段可以传值不等于业务效果已被保证（放弃/恢复等语义单独验证）。
- **不要用 `completedTime` 判断状态**：实测放弃会写入 `completedTime`，恢复为未完成时不保证清除该时间。
- 不要把子任务的完成值 `1` 当成任务的"已放弃"。

## 8. 安全边界

- **仅支持国内**：本版本仅支持国内滴答服务，API 出口固定 `https://api.dida365.com`、MCP 出口固定 `https://mcp.dida365.com`。可识别的国际/其他域名配置（如 `DIDA365_API_DOMAIN` 指向 `api.ticktick.com`）会在发送任何凭据之前失败，不做静默降级；也不能从 Token 字符串识别地区。
- **Token 不出现在参数、日志或输出中**：不回显 Token，不把 Token 写入命令行参数、请求体、`--check` 输出、错误回显或 metadata。
- **MCP 通道凭据来自凭据文件**：默认 `~/.dida365/token`，可用 `DIDA365_TOKEN_FILE` 覆盖。插件级 `headersHelper` 运行时，Claude Code 会移除名称含 TOKEN/SECRET/PASSWORD/KEY/AUTH 的环境变量，因此 `DIDA365_API_TOKEN` 在 MCP 连接时通常不可见；环境变量只是本地直调时优先生效的可选来源。凭据文件位于仓库与 `/sync-config` 之外，不随插件同步。
- **不读取 MCP OAuth 缓存**：OAuth 只覆盖 MCP 接入，API 补缺需要个人 Token；不得从客户端缓存提取凭据，也不得把 OAuth 当作 API 凭据来源。
- **自检用无秘密模式**：`uv run ${CLAUDE_PLUGIN_ROOT}/scripts/mcp_headers.py --check` 只输出配置状态（含 `token_source`、`token_present`），可用于排查"凭据来自环境变量还是凭据文件"；不要运行不带 `--check` 的辅助入口，也不要把它的认证头输出展示给用户。
- **执行器边界**：`dida365_api.py` 不跟随重定向、不自动重试任何请求、不覆盖 `/oauth/` 授权类操作；预演与错误信息同样不含凭据。

## 9. 失败分类

按错误类别处置，任何一类都不得成为自动切换通道或自动更换认证方式的理由：

| 现象 | 分类与处置 |
|---|---|
| 401 | 凭据问题（缺失、无效或过期）。按 setup-guide 检查并修复凭据；不用另一条通道重发同一操作。 |
| 403 | 权限问题（清单或操作权限不足）。说明权限原因，不要一概描述为令牌失效。 |
| 429 | 触发限流。说明情况并稍后重试；不把换通道当作绕过限流的方法。 |
| 超时/网络中断/5xx | 结果可能不确定，写操作尤其如此。先读回核验现状，再报告确定或不确定；不自动重试、不换通道重做。 |
| 工具参数错误 | 重新核对当前 schema 后修正参数，不以 API 透传绕过校验来试写。 |

无法核验时如实报告"结果未知"，不猜测执行结果。
