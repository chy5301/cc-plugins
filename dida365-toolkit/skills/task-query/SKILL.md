# 筛选和查询滴答清单任务

按任意条件筛选未完成或已完成的任务，统计数量、查看完成情况。本 skill 只读，不修改任何数据。

通道选择、工具命名发现、能力发现协议、批量部分失败、安全边界与失败分类统一见 `${CLAUDE_PLUGIN_ROOT}/references/tool-conventions.md`；使用任何滴答清单能力之前先读该文件，本文只补充查询相关的语义与覆盖范围说明。官方端点来源与已验证限制见 `${CLAUDE_PLUGIN_ROOT}/references/api-reference.md`。

## 分流：任意条件查询 vs 每日固定视角

- **本 skill**：条件是用户给定或可推断的——按清单、优先级、标签、状态、日期范围自由组合，或统计数量、查看已完成任务。
- **daily-review**：固定的"今天要做什么 / 有什么逾期的 / 帮我规划今天"每日视角。两者走同一套查询能力，区别只在于条件是任意的还是固定的。
- 用户只问"今天要做什么"这类固定视角，转 daily-review；条件明确的（如"这周标签是紧急的未完成任务"）留在本 skill。

## 接入前提

- **凭据来源**：MCP 通道固定使用默认凭据文件 `~/.dida365/token`；环境变量 `DIDA365_API_TOKEN` 是**可选且优先**的来源，但它只对本地/API 直接调用生效，不能替代默认凭据文件（原因与排查见 `tool-conventions.md` 第 8 节与 setup-guide）。
- 没有可用凭据时，说明缺什么并转入 setup-guide，不要在本 skill 里改动认证配置。
- 调用返回 401/403/429、超时或参数错误时，按 `tool-conventions.md` 第 9 节分类处置；这些是运行失败，不是能力缺口，不构成改用 API 重发同一操作、或更换认证方式的理由。

## 查询经官方 MCP 完成

查询默认走 `.mcp.json` 注册的 `dida365` 服务：

1. **先发现当前工具**：查看当前连接实际暴露的工具与 schema，按语义选择（清单列表、清单详情、条件筛选、已完成任务查询、单任务读取等）。工具名与参数以发现结果为准——插件模式下形如 `mcp__plugin_dida365-toolkit_dida365__<tool>`，OAuth 手动配置模式下命名空间可能不同；**不得凭记忆拼工具名，也不得写死唯一前缀**。
2. **先缩窄再取数**：能用清单范围、日期范围、状态、优先级、标签缩窄的，先缩窄，避免拉全量再在本地过滤。
3. **字段裁剪**：输出可能偏大，优先选参数更精确的查询方式；需要时用当前 schema 支持的字段裁剪参数，但不要为了"恢复 fields"为所有操作新增 API 双路调用。
4. **确认缺口才补缺**：只有 MCP 明确缺少所需工具或必需参数时，才按 `tool-conventions.md` 第 2 节的能力发现协议走 API 补缺路径；调用报错不算缺口。

## 三种日期语义：开始日、截止日、完成日

任务上的三种日期不是同一个东西，对应不同的筛选字段与工具，**不能用其中一个冒充另一个**：

| 语义 | 字段 | 含义 | 对应工具 |
|---|---|---|---|
| 开始日 | `startDate` | 任务排定开始、进入视野的日期 | 条件筛选工具的日期参数通常基于它 |
| 截止日 | `dueDate` | 任务应当完成的期限 | 需先确认筛选工具是否支持该字段；不支持时逐清单读取后在结果中筛 |
| 完成日 | `completedTime` | 完成动作发生的时间 | 已完成任务查询工具（按完成时间范围筛选） |

- **先看 schema 再下结论**：哪个工具支持按哪个字段筛选，以当前发现到的 schema 为准。官方存在 POST 查询接口，判断是否只读按操作语义而不是 HTTP 动词。
- **按截止日找逾期任务**：如果筛选工具只支持开始日，它给出的是"开始日已过"的粗筛，**不等于截止日逾期**，不得据此宣称逾期已查全。此时枚举相关清单（含 inbox）读取任务，再在结果中筛 `dueDate` 早于当前日期且 `status` 为 `0` 的任务，并在回答中说明覆盖了哪些清单。
- **不要用 `completedTime` 判断状态**：实测放弃也会写入该时间，恢复为未完成时不保证清除（见 `tool-conventions.md` 第 7 节）。完成日字段是用来查"什么时候完成的"，不是判断完成与否。
- **日期一律写完整 ISO 8601 并带明确时区**（如 `2026-04-05T14:30:00+0800`），"今天/昨天/本周"必须结合当前日期自行解析：本次迁移不再承诺短日期会被转换，请直接传完整时间戳。

## 常见查询场景

以下条件与对应工具参数以当前发现的 schema 为准：

- **高优先级未完成任务**：状态为未完成 + 优先级高（优先级取值 `0`=无、`1`=低、`3`=中、`5`=高，筛选时可组合多个取值）。
- **某个清单某段时间的任务**：先取清单列表核对清单身份（存在同名清单时展示候选并确认），再用清单 + 日期范围筛选。
- **带特定标签的未完成任务**：多标签是 AND 关系，需要全部匹配；标签名不确定时先向用户确认。
- **本周完成了什么**：用已完成任务查询工具，按完成时间范围筛选；同一范围里换日期字段查询的结果不是同一件事。
- **统计数量**：计数在 Agent 侧完成；命中多个清单时说明是按哪些清单统计的，不要给出"总数"而不说范围。

## 结果展示建议

建议以表格形式向用户展示关键信息，只保留用户关心的列：

| 列 | 说明 |
|---|---|
| 任务标题 | 必要时附任务 ID，便于后续操作引用 |
| 所属清单 | 清单名，属于虚拟 inbox 的单独标注 |
| 优先级 | 用 🔴🟡🔵⚪ 等标识区分高/中/低/无 |
| 截止日 | 早于今天的标注为逾期 |
| 状态 | 未完成 / 已完成（必要时注明已放弃） |

## 覆盖范围与截断

给出结果时一并说明这次查询**覆盖了什么、哪里可能不完整**：

- **覆盖范围**：查了哪些清单、是否包含虚拟 inbox、日期与状态的范围、用的是哪个日期字段（开始日/截止日/完成日）。
- **截断**：清单列表是分页的，**且不包含虚拟 inbox——清单列表为空不代表账号没有任务**。第一次返回通常不是全部：按分页继续跟页；命中分页上限或结果条数明显偏少时，明确说明"结果可能不完整"，不要把截断后的集合当作全量。
- **失败**：部分清单读取失败、超时或结果不确定时，报告失败的清单与未覆盖的部分，不把部分结果写成全部（见 `tool-conventions.md` 第 6、9 节）。

> 更全面的每日回顾（今日待办、逾期任务、高优先级、inbox）请使用 daily-review skill。
